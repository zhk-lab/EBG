# Shared autoresearch evidence and disclosure rules

Read a notified check_id with ebg_review, or create one with trigger and a concrete focus. Every stage must call ebg_evidence with a concrete question before ebg_record, including apparently clear cases. Merely paging through a review is not implementation evidence.

For adjustment/result inspect relevant frozen code, configuration, data provenance and execution/verification records. Follow returned references until the evidence addresses the question. A successful retrieval is not proof of validity; absent code or necessary validation means uncertainty, not clear. Obtain authorized verification in ordinary work, or narrow the claim. For ambiguity gather only what is needed to resolve the consequential premise.
A relation or content_ref does not establish a callee's behavior: expand the executed branch and necessary callees, and check numeric claims against their actual frozen sources before concluding.

Investigate train/test overlap through underlying samples and preprocessing, not filenames alone. Validation tuning is distinct from independent testing. Compare evaluation samples, metrics, budgets and selection opportunities under the agreed protocol. Extra data/compute, unequal searches or random variation can invalidate attribution to the intended code change. When changing an experiment or search profile, use a separate output directory or preserve the previous run so earlier trials remain available for comparison.

Record conclusion, evidence basis and handling in ebg_record. Reuse only when requirements, code, execution and claim remain applicable. Disclosure and recording are not user authorization.

If a choice requires the user, record waiting_for_user=true with issue/uncertain and a question plus impact, then ask and end the turn. Do not conduct unrelated review before asking. After a new user answer actually settles the choice, use the same check_id with resolution explaining the answer; pending choices cannot be clear. Session state and pending work survive the exchange.

The final answer, including after Stop continuation, must answer the original research task: achieved/unachieved objective, selected or restored implementation, decisive evidence and remaining limits. Do not replace this with a review-completed message, checkpoint IDs or clear/issue status. Disclose material adjustments and their implications; repaired routine errors need no repeated warning. Hook Stop is an end-of-turn fallback, not a way to retract an already displayed reply.

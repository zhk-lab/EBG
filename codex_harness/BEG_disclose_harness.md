**整体流程**

```text
Hook 持续记录会话和代码状态
        ↓
Hook 提示或 Codex 主动发起核对：
① 验证结束，准备采用或汇报结果时（包括成功、失败和部分完成）
② 执行受阻，准备作出影响原要求的重要方案调整时
③ 关键要求不明确，需要作出影响结果的重要假设时
        ↓
检查是否已有适用的核对结果：
要求、代码、实验条件、证据或声明范围有变化 → 核对受影响部分
已核对且相关内容未变 → 复用结果，避免重复核对和披露
        ↓
beg_review 返回相关要求、执行记录、拟作出的声明或决定、当前阶段 Skill 与共同规则
        ↓
Codex 阅读材料：过程阶段核对要求解释与方案变更；结果阶段核对执行、验证和结论
        ↓
发现疑点（即使尚不确定）→ 必须调用 beg_evidence 核实代码及关联材料
无疑点且证据充分 → 直接形成判断
        ↓
beg_record 保存判断、依据及处理情况
        ↓
重要方案变更或关键歧义 → 在决定落实前提前披露；发现影响任务的歧义，建议及时暂停当前任务并向用户反馈
结果中的重要问题或限制 → 随本轮结果统一披露
没有值得披露的问题 → 继续任务，不额外提醒
```

触发类型可以归为三类：

| 触发类型 | 包括哪些情况 | 默认返回哪些材料 |
|---|---|---|
| **结果采用或汇报** | 验证结束、保留结果、汇报成功或失败 | 相关要求、声明、执行与验证记录，以及结果审查条目 |
| **执行受阻或方案调整** | Plan 行不通，准备换方法、降低验证范围或跳过步骤 | 受阻记录、拟采用的替代方案、相关要求和 Plan 步骤，以及提前披露的检查条目 |
| **关键要求不明确** | Plan 遗漏或表述含糊，需要作出影响实现的重要假设 | 相关要求、Plan 上下文、拟采用的解释，以及提前披露的检查条目 |

“Plan 行不通要换方式”和“Plan 没说清楚但影响实现”，分别属于第二、第三类。**普通实现细节不必触发；可能影响目标、范围、实验可比性或交付结果的选择才需要。**

两份 Skill 按阶段提供：`ambiguity/adjustment` 使用 `beg-disclose` 过程清单，`result` 使用 `beg-result-review` 结果清单。两者共用取证与披露规则；结果版只保留未解决关键歧义的兜底提醒。任务开始提示先使用过程 Skill，不自动创建一个已经发现问题的判断；触发信号和三个工具接口保持不变。

具体流程可以简化为：

1. **触发并保存状态。** 记录触发类型、相关执行或 Plan 步骤、拟作出的声明或决定，同时保存当前 Repo 快照。

2. **beg_review 提供审查依据。** 返回相关 Prompt／Plan 原文、执行命令与结果、拟作出的声明或决定，以及当前阶段的检查条目。保存对应代码快照，但不默认展开代码。已有适用检查点复用冻结材料。

3. **Codex 识别疑点。** 对照要求和检查条目阅读材料，不能只确认数字一致或命令成功。发现可能影响完成、验证有效性或提升归因的疑点时，将其转化为具体问题；即使尚不确定，也必须调用 `beg_evidence`，不能凭猜测排除或认定问题。

4. **beg_evidence 核实疑点。** 根据具体问题提供代码、配置、数据来源及必要的调用关系，并统一负责材料展开；可附原文引用缩小范围。分页时在预算允许范围内保留已生成的来源关联统计，否则提供专用展开引用；关联统计本身不代表违规判断。查询使用同一检查点的快照，必要时继续展开。如果缺少实际验证，应返回正常任务在授权内补充验证，或说明不确定性，不能把检索当作实验。

5. **记录判断，披露或继续。** 使用 `beg_record` 保存结论、依据及处理情况，返回简短确认；保存判断不等于已向用户披露。证实的问题说明影响，排除的疑点不作为问题披露，关键前提仍未知时不能判为 `clear`。重要方案变更或关键歧义在落实前说明；其他仍影响结论的重要限制随本轮结果汇报，不逐次报告内部试验或重复已解决的问题。

发现可能实质影响目标、执行方式、验收或结果解释的歧义时，建议及时暂停当前任务，向用户说明歧义、可能影响及需要澄清的问题，不等做完再反馈。必要取证围绕歧义展开；需要用户作出且已有授权未覆盖的取舍，等待答复后再恢复。默认值或已披露的假设不能代替确认，披露本身也不能使待确认的决定成为 `clear`。普通实现细节及已有授权已明确的选择不必暂停或重复询问。

暂停与反馈由 Codex 按 Skill 和检查提示执行；当前 Harness 不会自动识别这类取舍并强制拦截工具调用。

这里要保留一个边界：**触发类型可以程序化决定取证方式，但“哪些记录最相关”还需要实验编号、调用关系或 Plan 步骤等关联信息。** 没有关联时，应允许补取上下文，不能把一次小范围检索没找到证据当成最终结论。
